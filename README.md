# The Squishy Pinball Machine

Natasha's virtual pinball machine.

Engine: Godot **4.7.2**. From the repo root:

    godot --headless --import && godot --path .

Tests (never run `godot -s tests/…` directly — that writes the real save
directory and can wipe a high score):

    ./tests/run_all.sh

## Web export (T26 / D-045)

One HTML5 build is the delivery route for both a Chromebook and an iPad
(D-042). The Mac desktop game is unchanged. `export_presets.cfg` and
`export/` stay gitignored (D-008); the preset is generated by the script
below, and this section is enough to recreate it by hand.

### 1. Install the web export templates

Godot will not export until the official templates for **4.7.2.stable**
are on disk. They are a ~1.3 GB download and are **not** in this repo.

**From the editor:** Editor → Manage Export Templates… → Download and
Install. On this Mac they land in
`~/Library/Application Support/Godot/export_templates/4.7.2.stable/`.

**From the script:** `bash tools/export_web.sh --download` fetches
`Godot_v4.7.2-stable_export_templates.tpz` from the official
godot-builds release and extracts only `web_nothreads_debug.zip` and
`web_nothreads_release.zip` (the files this preset uses).

`tools/export_web.sh` without `--download` **exits non-zero** if
`web_nothreads_release.zip` is missing. It will not emit a half-written
`export/web/` that white-screens in a browser.

### 2. The `Web` preset

`bash tools/export_web.sh` writes `export_presets.cfg` every run. To
recreate the same preset in the editor (Project → Export → Add… → Web),
use these options and nothing else:

| Option | Value | Why |
| --- | --- | --- |
| Preset name | `Web` | What the script passes to `--export-release` |
| Export path | `export/web/index.html` | `index.html` is what a static host serves |
| Extension Support | off | This project has no GDExtension |
| Thread Support | **off** | No `Thread` / `WorkerThreadPool` in `autoload/` or `scripts/`. A single-thread build does not need `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy` headers. |
| VRAM Texture Compression / Desktop | on | Chromebook / desktop browsers (S3TC/BPTC) |
| VRAM Texture Compression / Mobile | on | iPad / mobile browsers (ETC2/ASTC). Requires `rendering/textures/vram_compression/import_etc2_astc=true` in `project.godot` — Godot 4.7.2 refuses the export without it. |
| Export Icon | on | Project icon (`assets/icons/glitter_drop.png`) becomes `index.icon.png` plus `index.apple-touch-icon.png`. `DisplayServer.set_icon` is a no-op in a browser (D-032). |
| Custom HTML Shell | empty | Godot's default shell. Page title is the project name. |
| Head Include | `<meta name="description" …>` | Host-page presentation only. Godot already writes the icon `<link>` tags. |
| Canvas Resize Policy | Adaptive | Fills the browser; `canvas_items` / `keep` (D-003) letterboxes inside the canvas |
| Focus Canvas on Start | on | Keyboard / tap reach the game without an extra click |
| Experimental Virtual Keyboard | off | Name entry uses the real `LineEdit`; a real iPad settles this (D-043) |
| Progressive Web App | off | Hosting is not part of this task |

### 3. Build

From a clean checkout, after `godot --headless --import` (the script
also imports):

    bash tools/export_web.sh

That writes `export/web/index.html` plus the `.js` / `.wasm` / `.pck` /
favicon. `export/` is gitignored — do not commit it.

### 4. Serve and play

A static file server is enough. Isolation headers are **not** required
for this single-thread build; `python3` is a valid local check because
it does not send them:

    python3 -m http.server 8080 --directory export/web

Then open `http://127.0.0.1:8080`. An exporter exit code of zero is not
evidence the game works — load the page, launch a ball, use both
flippers, drain, and reach game over, and read the browser console.

### Saves (`user://` in a browser)

Profile, high score, settings (theme), and the app-icon choice are
written to browser storage (IndexedDB), not a desktop folder. They are
**per browser and per origin**. They survive a normal reload. They
vanish when the player clears site data, uses a private window, or
switches browsers — which is exactly why the cloud profile (D-037)
exists.

A write-then-immediate-reload can lose a flush that has not landed yet.
Reload after the title (or settings) has come back; that is a finished
write, not a race.

### Leaderboard from a local origin

A web build always talks to `https://squish-leaderboard.onrender.com`
(`Leaderboard.BASE_URL`; a browser has no env-var override). Until the
page's HTTPS origin is listed in `SQUISH_ALLOWED_ORIGINS` (D-044), the
browser will refuse those requests. That is correct. The title and game
over already show the offline copy ("Leaderboard offline"); the table
stays playable. Do not point `BASE_URL` at a proxy or ask for the
allowlist to be opened just to make a local demo look live.

### Host (not deployed by this task)

Render already serves the leaderboard and can serve `export/web/` as a
static site. That is the obvious host: one workspace, HTTPS, and then
the planner adds that origin to `SQUISH_ALLOWED_ORIGINS`. GitHub Pages
would also work; it is not required.
